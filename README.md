# 抽成审计器（v0）

![ci](https://github.com/zjdyzww/audit-kit/actions/workflows/ci.yml/badge.svg)

**你的店，被平台抽走了多少？** 把这个数字算出来。

导入平台结算单，它告诉你：实际费率是多少、按公示费率应抽多少、差额多少、有没有重复扣费。

> 纯本地运行：不联网、不上传、不留存任何数据。你的账单不会离开你的电脑。

## 为什么做这个

抽成每高 1 个百分点，约等于吃掉小微商户 20% 的利润（小微净利率约 4.9%）。
但多数店主从来没有算过这个数——因为平台导出的结算单字段名各不相同，很难直接比。

## 用法

```sh
node audit.mjs --input 结算单.csv --declared-rate 0.06
```

输出：

```
实际抽成      ¥106,596.90   费率 8.30%
GMV           ¥1,284,300.00
公示费率      6.00%   应抽 ¥77,058.00
差额          ¥29,538.90
异常          3 项
```

加 `--json out.json` 可导出机器可读结果。

## 一条命令看效果（不需要你的数据）

```sh
node examples/verify-demo.mjs      # 生成演示数据并独立核验
node audit.mjs --input examples/演示-结算单.csv --declared-rate 0.06
```

演示数据 120 笔，交易额 ¥120,000，平台实际抽成 ¥11,077（**9.23%**），
公示费率 6.00% 应抽 ¥7,200 —— **差额 ¥3,877**，外加 5 条异常。

期望值由 `examples/verify-demo.mjs` 按算式独立推出，**不是抄程序输出**；
两者不一致就 `DEMO FAIL`。这是防止「自己验自己」的循环论证。

## 用你自己的列名（不需要等适配器）

平台导出的列名千奇百怪，但**不需要改你的文件**：

```sh
# 1) 先让它猜一份映射草案
node audit.mjs --input 你的结算单.csv --emit-mapping > map.json

# 2) 打开 map.json 核对/修正列名，然后执行
node audit.mjs --input 你的结算单.csv --mapping map.json --declared-rate 0.06
```

草案只做表头名字匹配，**不读你的数据**。映射指错列会直接报错并列出现有列名，不会算出一个看着像真的错数。

## 输入格式

**CSV（UTF-8，可带 BOM）或 .xlsx 均可直接读**，必需列：

`order_id, settle_date, gmv, commission, service_fee, refund, payout`

含义见 [spec.md](spec.md)。

`.xlsx` 由零依赖的内置读取器解析（只用 Node 自带 zlib，不装任何包）。
Excel 里的日期是序列号，会自动换算成 `YYYY-MM-DD`。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 干净，无异常 |
| 1 | 有异常（报告有效，异常已列出） |
| 2 | 输入错误（缺列/非数字），**不产出报告** |
| 3 | 自检失败 |

缺列时它不会"猜"，会直接告诉你缺哪几列——**半份报告比没有报告更危险**。

## 自检

```sh
node audit.mjs --self-test
```

含 5 条负例：缺列、非数字、佣金>GMV、到账不符、重复订单号。

## 状态与边界

- v0 **只支持 `generic` 适配器**（列名已是标准名）。
- 美团/饿了么等平台的导出格式：**尚未实现**（UNVERIFIED）——没有真实样本就不猜列名。
  如果你愿意提供一份**脱敏**的结算单，我按你的格式写适配器。
- 不联网、不做税务计算、不给法律意见、不推荐"该换哪个平台"——只出数字，判断归你。
